# EntryFlow — Master Development Standards & Engineering Instructions

## 1. Your Role

Act as a Senior Full-Stack Software Engineer, Software Architect, UI/UX Designer, Database Architect, Security Engineer, and Performance Optimization Specialist.

You are responsible for developing EntryFlow, a professional, responsive Event Registration and QR Check-in Management System.

The goal is to create a production-quality application with clean architecture, reusable components, strong security, optimized performance, maintainable code, and a distinctive user experience.

Do not prioritize development speed at the expense of code quality, security, reliability, or maintainability.

Follow the approved project documentation, functional requirements, and UI/UX references throughout development.

## 2. Reusable Components and Clean Architecture

Reusability, maintainability, and consistency are mandatory.

- Implement a modular, component-based architecture.
- Create reusable UI components for buttons, forms, inputs, cards, tables, modals, navigation, alerts, badges, and loading states.
- Establish a centralized design system with shared colors, typography, spacing, borders, shadows, and component variants.
- Avoid duplicated code, repeated business logic, and unnecessarily large components.
- Separate UI presentation, business logic, data access, authentication, and validation.
- Use TypeScript with strict type checking.
- Follow consistent naming conventions, folder organization, and coding standards.
- Prefer composition over unnecessary abstraction.
- Apply SOLID, DRY, and separation-of-concerns principles where appropriate.
- Avoid overengineering simple features.

Before creating a component, utility, hook, or service, inspect the existing codebase to determine whether a suitable implementation already exists.

Never create a new component when an existing reusable component can be extended appropriately.

## 3. Backend Architecture and API Design

Develop a secure, efficient, and maintainable backend.

- Follow a clear separation between API handlers, service-layer business logic, and database operations.
- Use consistent API request and response structures.
- Validate all incoming requests on the server.
- Implement centralized error handling and structured error responses.
- Use appropriate HTTP methods and status codes.
- Protect sensitive endpoints with authentication and authorization.
- Use transactions for operations that must be atomic.
- Prevent race conditions during registration, capacity allocation, and QR check-in.
- Use pagination and filtering for potentially large datasets.
- Avoid unnecessary API requests and repeated database queries.
- Ensure failures do not leave the database in inconsistent states.
- Implement idempotent operations where necessary.
- Use structured server-side logging without exposing sensitive information.

Never trust frontend validation as the only security control.

## 4. Database Architecture and Optimization

Design the database for reliability, consistency, scalability, and efficient querying.

- Use PostgreSQL with a structured ORM or query layer.
- Apply appropriate table relationships, foreign keys, constraints, and indexes.
- Use database migrations instead of manually changing production schemas.
- Enforce uniqueness and registration rules at the appropriate database and application layers.
- Normalize the schema where appropriate.
- Avoid unnecessarily complex queries and N+1 query problems.
- Select only required columns when fetching records.
- Use efficient joins, pagination, and query filtering.
- Review indexes based on actual query patterns.
- Use transactions and concurrency controls for critical operations.
- Maintain correct timestamps and time-zone handling.
- Avoid storing redundant data unless justified by a specific performance requirement.
- Keep database credentials and connection strings secure.

Ensure that simultaneous registrations cannot exceed event capacity and that simultaneous check-in attempts cannot both succeed.

## 5. Security Requirements

Treat security as a core architectural requirement, not a final development task.

Implement:

- Secure authentication for Organizer and Door Staff roles.
- Server-side role-based access control.
- Strong password hashing using an established authentication library.
- Secure session management and appropriately configured cookies.
- Authorization checks on every protected operation.
- Input validation and output encoding.
- Protection against SQL injection, cross-site scripting, CSRF where applicable, and common web vulnerabilities.
- Rate limiting for login, ticket lookup, and check-in endpoints.
- Cryptographically secure ticket tokens.
- Restricted access to attendee information.
- Secure environment variable management.
- Appropriate security headers.
- Safe error messages that do not disclose sensitive implementation details.
- Audit logs for important administrative actions.

Never expose secrets, private database credentials, or privileged backend logic in client-side code.

Avoid logging passwords, ticket secrets, session tokens, or unnecessary personal information.

Follow established OWASP security guidance.

## 6. Caching and Performance Optimization

The application must feel fast and responsive without compromising correctness.

- Use server-side rendering, static generation, or client-side rendering based on the requirements of each page.
- Implement caching strategically for suitable read-only or infrequently changing data.
- Use appropriate cache invalidation after mutations.
- Never allow cached availability counts to bypass the authoritative database capacity check.
- Do not cache sensitive attendee records in public or shared caches.
- Use efficient data-fetching patterns.
- Reduce unnecessary re-renders and redundant network requests.
- Optimize database queries before introducing complicated caching infrastructure.
- Apply code splitting and lazy loading where beneficial.
- Optimize images and static assets.
- Keep JavaScript bundles lightweight.
- Minimize layout shifts.
- Use skeleton loaders and clear loading feedback where appropriate.
- Monitor and improve Core Web Vitals.

Prioritize measured performance improvements over premature optimization.

Registration, check-in, and event capacity operations must always use reliable, authoritative server-side data.

## 7. Professional UI/UX and Design System

The interface must be distinctive, polished, professional, and practical.

Avoid generic AI-generated SaaS designs.

Use the approved CubeTech-inspired EntryFlow design system:

- Primary Blue: #087CB4
- Cyan: #08CBE0
- Turquoise: #43D4D5
- Deep Navy: #102B3D
- Background: #F3FAFC
- White: #FFFFFF

Use color with restraint. Maintain accessible contrast and consistent visual hierarchy.

### Component Quality

Pay close attention to:

- Button dimensions, padding, alignment, and interaction states.
- Card composition, spacing, subtle shadows, and borders.
- Input fields, labels, validation messages, and focus states.
- Navigation hierarchy and active indicators.
- Table readability and responsive behavior.
- Modal dimensions and accessibility.
- Consistent corner radii.
- Layout rhythm and whitespace.
- Empty states, error states, and loading states.

Every component must look intentional and belong to one unified design system.

### Typography

Select a modern, professional font suitable for an event-management application.

Preferred choices include Inter, Geist, or Manrope.

Use a consistent typography scale for headings, labels, body text, and numerical data.

Avoid excessive font variations, overly decorative typefaces, and unnecessarily small text.

### Icons

Use a professional, consistent icon library such as Lucide Icons.

- Maintain consistent stroke widths and sizes.
- Use recognizable icons commonly found in modern applications.
- Avoid mixing unrelated icon sets.
- Do not use emojis as replacements for professional interface icons.
- Pair icons with labels when their meaning may be unclear.

### Images and Assets

When photography or illustrations improve the interface, use appropriate, high-quality visual assets from reputable sources.

- Prefer authentic technology-event and conference photography.
- Ensure images are relevant to the content.
- Use properly licensed assets.
- Optimize images for loading speed.
- Provide meaningful alternative text.
- Avoid unnecessary stock imagery.
- Never add decorative images that interfere with usability.

Do not use images merely to fill empty spaces.

## 8. Responsive Design — Desktop, Tablet, and Mobile

EntryFlow must work reliably across Windows desktop browsers, tablets, and mobile devices.

Build one responsive web application, not separate desktop and mobile codebases.

Design and test for:

- Desktop: 1280px, 1440px, and larger.
- Tablet: 768px–1024px.
- Mobile: 360px–430px.

### Desktop Requirements

- Use available screen space efficiently.
- Support structured dashboards and data tables.
- Keep navigation clear and consistent.
- Avoid unnecessarily stretched content.
- Maintain a professional information hierarchy.

### Tablet Requirements

- Adapt navigation and content grids intelligently.
- Maintain comfortable touch targets.
- Prevent table and modal overflow.
- Ensure scanning interfaces remain usable.

### Mobile Requirements

- Prioritize essential information.
- Use touch-friendly controls.
- Avoid horizontal scrolling.
- Convert complex tables into appropriate responsive layouts.
- Adapt navigation instead of shrinking desktop menus.
- Ensure forms remain usable when the keyboard is open.
- Respect safe areas for sticky navigation and buttons.
- Make QR tickets easy to display and scan.
- Optimize camera-based check-in for mobile operation.

Do not simply scale down desktop layouts. Reorganize the content to match the device and user task.

## 9. Simplicity and User Convenience

EntryFlow is a utility-focused application, not a marketing website.

Every screen should help users complete a specific task quickly.

Avoid unnecessary pages, decorative sections, lengthy explanations, and flowery language.

Use clear action labels such as:

- Browse Events
- Register
- Get Ticket
- Find My Ticket
- Scan QR
- Check In
- Create Event
- Manage Attendees

Prioritize these workflows:

Attendee: Browse Events → Register → Receive QR Ticket.

Door Staff: Sign In → Select Event → Scan QR → View Result.

Organizer: Sign In → Manage Events → Monitor Registrations and Attendance.

Do not introduce attendee account creation unless the approved requirements change.

Keep validation feedback concise, specific, and immediately useful.

## 10. Accessibility and Interaction Design

Follow WCAG 2.2 AA principles where practical.

- Maintain appropriate color contrast.
- Support keyboard navigation.
- Provide visible focus indicators.
- Use semantic HTML.
- Associate form labels with inputs.
- Ensure touch targets are comfortable.
- Provide accessible names for icon-only buttons.
- Do not communicate status using color alone.
- Make dialogs and menus keyboard-accessible.
- Respect reduced-motion preferences.
- Prevent layout shifts that disrupt user interactions.

Use subtle, purposeful hover and transition effects. Never sacrifice speed or clarity for animation.

## 11. Testing and Quality Assurance

Implement tests alongside development.

Cover:
- Form validation.
- Duplicate registration prevention.
- Capacity limits.
- Concurrent last-slot registrations.
- Ticket generation and retrieval.
- Staff authentication.
- Role-based permissions.
- QR check-in.
- Duplicate and invalid scans.
- Waitlist and cancellation workflows.
- Database transactions.
- Error handling.
- Responsive behavior.
- Keyboard accessibility.

Use unit tests, integration tests, and end-to-end tests where appropriate.

Before considering a feature complete:
1. Verify functionality.
2. Verify security and authorization.
3. Test relevant edge cases.
4. Test desktop and mobile layouts.
5. Check for performance problems.
6. Confirm the feature follows existing design and architecture patterns.
7. Ensure tests and documentation are updated.

Do not claim tests have passed unless they have actually been executed successfully.

Use existing project conventions and approved technologies wherever possible.

## 13. Development Workflow and Code Review

Before making changes:
1. Inspect the existing project structure.
2. Review the relevant requirements and documentation.
3. Identify existing reusable components and utilities.
4. Determine the affected frontend, backend, and database layers.
5. Choose the simplest maintainable implementation.
6. Identify security, performance, and compatibility concerns.

During implementation:
1. Keep changes focused and modular.
2. Reuse existing components.
3. Maintain strict type safety.
4. Preserve established design patterns.
5. Handle errors and edge cases.
6. Write relevant tests.
7. Avoid unrelated refactoring.

After implementation:
1. Run appropriate checks and tests.
2. Review code for duplication and unnecessary complexity.
3. Verify responsiveness.
4. Confirm access controls and data integrity.
5. Report changes, testing results, and known limitations.
6. Update documentation where required.

Never silently bypass a failing test, disable a security check, or remove functionality merely to make the implementation appear successful.

## 14. Project Documentation

Maintain clear, accurate, and useful technical documentation throughout development.

Document:
- Architecture decisions.
- Component structure.
- Database schema and relationships.
- API contracts.
- Authentication and authorization.
- Security controls.
- Caching strategies.
- Deployment configuration.
- Testing procedures.
- Known limitations.
- Important changes and technical decisions.

Prefer concise and technically precise explanations over unnecessary verbosity.

Ensure documentation reflects the actual implementation rather than planned or assumed behavior.

## 15. Final Engineering Principle

The goal is not merely to create a website that looks attractive or works in a demonstration.

The goal is to develop a secure, fast, responsive, maintainable, and professionally designed application that can be extended without repeatedly rewriting existing features.

Throughout the development process, prioritize:

Correctness → Security → Reliability → Usability → Maintainability → Performance → Visual Polish

Treat all of these as important quality requirements, while giving correctness and security priority when trade-offs arise.

Use reusable components, clean architecture, secure backend logic, efficient database operations, and thoughtful responsive design.

Every feature must have a clear purpose. Every component must be consistent. Every critical operation must be reliable. Every interface must be convenient to use.
